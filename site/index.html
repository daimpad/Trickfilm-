    Alle Befehle

    Prototyp

    Szene bauenEigenes Fenster

    Die Szene läuft so wie im fertigen Film. Leertaste spielt ab, die Pfeiltasten gehen ein Bild vor oder zurück, Sprungmarken führen zu jedem Beat. Erlaubt der Browser keinen Ton ohne Klick, wartet die Szene auf „Abspielen“.

    Eine Datei, die nichts nachlädt; die Bibliothek steckt als Import-Map darin. Zeitgeber ist performance.now(). Ein Geräusch klingt, wenn die Wiedergabe über seinen Zeitpunkt läuft; Springen löst nichts aus. Ohne Erlaubnis für Ton wartet die Szene auf „Abspielen“.

    Posen-Editor

    ÖffnenSzene bauen, Schritt 5

    Hier stellt man eine Figur direkt auf der Bühne, statt Winkel einzutippen.

    • Griffe: Die Hüfte verschiebt die ganze Figur, Rumpf und Kopf neigen sich, Hände und Füße folgen ihrem Ziel.
    • Reichweite: Ein Ring zeigt, wie weit die Hand reicht; rot heißt, das Ziel liegt zu weit weg.
    • Genau: Pfeiltasten verschieben den Griff um 1 px, mit Umschalt um 8 px.
    • Schlüsselposen: auf der Zeitleiste setzen und abspielen; der Editor schreibt daraus den Code für die Szene.

    npm run editor -- --szene <ID> --figur A legt das Standbild der Szene unter die Figur.

    // geometry.js
export const POSEN_A = { archetyp: 'stehend-profil', torso: [[0, 0], [1, 17.1]], armF: { ziel: [[0, 1060, 470], [1, 1040, 520]] } };
// animation.js
const A = posenZustand(rig('stehend-profil'), POSEN_A, t);

    Zwischen den Schlüsseln wird weich verbunden. Arme mit Handzielen laufen über greife(), damit der Build ihre Reichweite prüft.

    Teile-Werkstatt

    ÖffnenFigur zeichnen

    Statt eine ganze Vorlage auszufüllen, zeichnet man jedes Körperteil für sich, in beliebigem Programm und Maßstab. Alle Dateien bleiben im Browser.

    • Laden: je Teil eine SVG-Datei; heißt sie nach dem Teil (kopf.svg, hand.svg), findet sie ihren Platz selbst.
    • Einpassen: Die Werkstatt legt das Teil aufs Skelett; korrigiert wird durch Ziehen am Teil und am roten Griff.
    • Ableiten: Fehlende hintere Glieder und Handformen entstehen aus den vorhandenen.
    • Prüfen: Sechs Testposen zeigen die Figur in Bewegung; eine Lücke an einem Gelenk erscheint rot.
    • Farben: Kleidung und Zubehör zuordnen, damit jede Szene sie umfärben kann.
    • Ausgeben: ein ZIP mit allen drei Profilfiguren, bereit für den Importer.

    npm run teile erzeugt die Seite örtlich. Das ZIP unter figuren/teilesaetze/ entpacken und mit npm run figuren:import -- satz-01 einlesen. Gelesen werden Pfade, Grundformen, Transformationen, CSS-Klassen und Bögen; Konturen werden auf 4 oder 6 px gerundet.

    Hörprobe

    Geräusche pflegen

    Alle Varianten jedes Geräuschs nebeneinander, mit Länge, Lautheit und einer Gütezahl. Sie läuft im Repository, weil sie alle Rohaufnahmen braucht.

    1. npm run sfx:hoerprobe erzeugt out/sfx/hoerprobe.html.
    2. Je Geräusch eine Variante wählen, bei einem Vorrat mehrere, „bestätigt“ setzen und die CSV-Datei herunterladen.
    3. npm run sfx:hoerprobe -- --uebernehmen auswahl.csv, dann npm run sfx:normalisieren.

    Je Variante: Länge, Einsätze, Lautheit, Spitzenpegel, Vorgeräusch und Gütezahl (kleiner ist sauberer), bei Lauten die Stimme. Die Wahl steht in lib/sfx/auswahl.yaml; npm run sfx:normalisieren -- --vorschlag wählt vorläufig und lässt Bestätigtes stehen.

    Szene bauen

    Posen-EditorPrototypBewegung

    Eine Szene besteht aus vier Dateien und wird vor dem Abspielen Bild für Bild geprüft.

    1. Anlegen: npm run szene:neu -- FILM-01-name kopiert die Vorlage.
    2. Brief (brief.yaml): Sprechtext wörtlich, These und Pointe in je einem Satz, Figuren mit Charakter, Beats mit Zeiten und eine Bildbeschreibung für Menschen, die es nicht sehen.
    3. Geometrie (geometry.js): wo Figuren und Dinge stehen, wohin Hände greifen.
    4. Aufbau (scene.js): Figuren und Requisiten von hinten nach vorn.
    5. Bewegung (animation.js): was zu jedem Zeitpunkt geschieht; Posen im Posen-Editor.
    6. Geräusche im Brief unter sfx: welche Ereignisse klingen, etwa jeder dritte Tastenanschlag; siehe Geräusche pflegen.
    7. Bauen: npm run szene:bauen -- FILM-01-name prüft die Szene und erzeugt den Prototyp.
    8. Ansehen: npm run szene:kontaktbogen -- FILM-01-name erzeugt neun Standbilder. Liegt etwas falsch vor dem Körper, greift ein Arm durch den Tisch, ist die Pointe auch klein lesbar?
    9. Abspielen: szenen/FILM-01-name/dist/index.html
    10. Protokoll: npm run szene:protokoll -- FILM-01-name
    11. Anhalten und kurz melden, was fertig ist.

beschriftungen: { links: "Eingabe", mitte: "", rechts: "Bestätigung" }
textaequivalent: "Zwei bis vier Sätze, die das Bild beschreiben."
sichtung: { lesbarkeit_960: offen, synchron: offen }

    Was der Build prüft

    • Brief und Code stimmen überein; nur Farben der Tokens.
    • Keine Animationen, Verläufe, Filter, Masken oder Rundungen im Bild.
    • Für jedes Bild: jede ID, jedes Attribut, kein NaN.
    • Jede Hand erreicht ihr Ziel; Text bleibt aus der Schutzzone und steht lange genug.
    • Gleiche Zeit ergibt denselben Zustand.

    Figur zeichnen

    Teile-WerkstattArchetypen

    Eine Figur ist eine Gliederpuppe mit festem Skelett; gezeichnet wird nur ihr Aussehen, der Teilesatz.

    Aus Einzelteilen (einfacher)

    1. Jedes Körperteil als eigene SVG-Datei zeichnen, Name nach dem Teil.
    2. In der Teile-Werkstatt laden, einpassen, prüfen.
    3. ZIP entpacken unter figuren/teilesaetze/, einlesen: npm run figuren:import -- satz-01

    Mit der Zeichenvorlage

    1. figuren/vorlage_<archetyp>.svg nach figuren/teilesaetze/satz-01/ kopieren.
    2. Jedes Teil in die Ebene mit seinem Namen zeichnen (torso, head, armF-upper …) und dabei die blauen Kreise an den Gelenken abdecken, sonst entstehen beim Drehen Lücken.
    3. Kleidung in Schlüsselfarben zeichnen: Magenta, Gelb, Grün. Diese Flächen färbt jede Szene um; alles andere bleibt, wie gezeichnet.
    4. Als SVG exportieren und einlesen.

    Der Importer prüft Teile, Ebenen, Formen, Farben und Konturen (4 oder 6 px), verschiebt jedes Teil um seinen Drehpunkt und dreht jedes Gelenk auf −60°, 0°, +60° und +120°. Lücken meldet er in figuren/import.tsv; Zeichnungen ändert er nie.

    Exportregeln: Präsentationsattribute, Ebenennamen als IDs, keine Verläufe, Filter, Masken, Schatten, Deckkraft, Texte oder Bilder.

    Geräusche pflegen

    HörprobeKlangregeln

    Zeitpunkte setzt niemand von Hand: Die Werkstatt spielt die Bewegung Bild für Bild ab und erkennt, wo etwas anschlägt, losgeht, ankommt oder erscheint.

    In einer Szene

    1. Im Brief unter sfx sagen, welche Ereignisse klingen und welches Geräusch aus dem Katalog dazugehört.
    2. npm run sfx:cues -- FILM-01-name --stichprobe schreibt die Geräuschliste und zeigt je Ereignis das Bild davor, darauf und danach.
    3. Neu bauen; der Prototyp spielt mit.

    Bibliothek erweitern

    1. npm run sfx:kosten listet, was fehlt, und schätzt die Credits; generiert wird erst nach Freigabe der Regie.
    2. Generieren über den ElevenLabs-Connector; npm run sfx:ablegen -- liste.tsv prüft jede Datei und schreibt ihre Herkunft.
    3. In der Hörprobe wählen; npm run sfx:normalisieren schneidet Stille ab, kürzt auf einen Anschlag und bringt alles auf denselben Pegel.
    sfx:
  ereignisse: { anschlag: { cue: tastenanschlag, ausduennen: 3 }, erscheinen: { cue: bestaetigung } }
  quellen:
    anschlag: [ { pfade: [A.armF.hand.y, A.armB.hand.y], beat: tippen, figur: A } ]
    erscheinen: [ { pfad: haken.deckkraft, beat: haken } ]
  stumm: []
  laute: [ { beat: reaktion, versatz_s: 0.2, cue: laut-erleichtert, figur: A } ]

    Erkennung in lib/events.js: Tiefpunkt, Beginn, Nulldurchgang, Bewegungsbeginn und -ende, Aufprall, Hüllkurve, Schwelle. Ausführlich in docs/GERAEUSCHE.md.

    Grundideen

    Die Werkstatt baut kurze Szenen mit Menschen, Geräten und Zeichen, unabhängig von einem Auftrag. Inhalte und Erscheinungsbild kommen später als Eingaben dazu.

    • Jedes Bild wird gerechnet

      Zu jedem Zeitpunkt ergibt sich das Bild aus einer Rechnung. Gleiche Eingabe, dasselbe Bild.

    • Figuren sind Gliederpuppen

      Ein festes Skelett trägt austauschbare Zeichnungen: verschiedene Menschen, dieselben Bewegungen.

    • Klang aus Bewegung

      Wo eine Hand auf die Tastatur trifft, entsteht ein Anschlag, nicht dort, wo ihn jemand hinsetzt.

    • Geprüft am Bild

      Standbilder, die ein Mensch ansieht, und Prüfungen, die über jedes einzelne Bild laufen.

    lib/ ist DOM-freies JavaScript und läuft im Prototyp, in Node und in Remotion. Eine Szene: brief.yaml, geometry.js, scene.js, animation.js mit computeState(t). 1920 × 1080, 30 Bilder je Sekunde.

    Grundsätze

    Sie halten Szenen wiederholbar, prüfbar und unabhängig vom einzelnen Rechner.

    1. Jedes Bild ist eine Funktion der Zeit. Nichts läuft von selbst; Zufall nur mit festem Startwert.
    2. Die Bibliothek ist unabhängig vom Browser. Dieselbe Rechnung läuft im Prototyp, in den Prüfungen und im Video.
    3. Geometrie ist Daten. Positionen, Maße und Farben stehen in eigenen Dateien.
    4. Bild und Ton werden nie beide geraten. Mit Aufnahme folgt die Bewegung den Wortzeiten, ohne wird geschätzt und markiert.
    5. Geräusche entstehen aus der Bewegung.
    6. Was gerechnet ist, wird nie von Hand gepflegt. Erzeugte Dateien werden neu erzeugt, nie nachgebessert.
    7. Was am Bild zu prüfen ist, wird am Bild geprüft.
    8. Ein Lauf, der etwas nicht weiß, sagt es. Kein leeres Ergebnis, das wie „nichts zu tun“ aussieht.
    9. Kein Netz beim Rendern. Was generiert wird, liegt vorher im Repository.
    10. Keine Geheimnisse im Repository. Schlüssel kommen nur aus der Umgebung.

    Verboten im Bildcode: CSS-Animationen, SMIL, transition, requestAnimationFrame als Zeitgeber, GSAP, Framer Motion, Math.random, Date.now. Zufall über prng(seed). npm run verboten sucht Verstöße.

    Figuren

    Figur zeichnenPosen-Editor

    Eine Figur besteht aus Archetyp (Skelett), Teilesatz (Zeichnungen), Palette und Blickrichtung. Sie hat kein Gesicht; Gefühle zeigen sich in Haltung, Tempo und Pausen.

    ArchetypWofürBeweglich
    sitzend-profilSchreibtisch, Schalter, GesprächRumpf, Kopf, Arme mit Händen; der Fuß kann wippen
    stehend-profilGehen, Warten, Tragendazu Beine mit Füßen und Gang
    stehend-frontalZeigen, Erklären, ReagierenArme seitlich, Schultern, „vor dem Körper halten“
    oberkoerper-nahReaktion, Dialog, PointeOberkörper in größerem Maßstab

    Maße in figuren/rig-spezifikation.json: Ober- und Unterarm je 90 px, Schulter 130 px über der Hüfte, Boden y 760, Tisch y 560. Zustand im Figurenrahmen: Blick nach rechts, Winkel vorwärts positiv, Arme absolut, Kopf relativ zum Rumpf; das Rig spiegelt selbst.

    Bewegung

    Szene bauenPosen-Editor

    Bewegung entsteht aus wenigen Bausteinen, die sich addieren.

    • Kurven geben den Charakter: weich, mit Anlauf, mit Überschwingen oder von Pose zu Pose.
    • Handziele: Man sagt, wo die Hand sein soll; die Gelenkwinkel rechnet die Werkstatt und meldet zu ferne Ziele.
    • Gang: Der tiefste Fuß steht immer auf dem Boden, das Knie zeigt nach vorn.
    • Spielweise: Gefühle wie konzentriert, genervt, überrascht oder erleichtert sind Rezepte für Haltung und Tempo.
    • Charakter: Tempo, Grundhaltung, Stärke der Reaktion und eine kleine Eigenheit wie Fußwippen.

    Der Witz liegt in der Situation, nie in der Person. Eine Pointe folgt auf einen Anlauf.

    Geräusche

    Geräusche pflegenHörprobe

    Dezent und eher zum Schmunzeln: eine etwas zu eifrige Tastatur, ein Drucker, der kurz nachdenkt.

    • Nie Boing, Fanfare, Lachen, Applaus oder Musik.
    • Drei bis sechs Arten je Szene, höchstens sechs Geräusche je Sekunde.
    • Nur Physisches klingt; eine Grafik, die bloß einblendet, bleibt still.
    • Höchstens ein Laut wie „oh?“, in vier Stimmen zur Wahl.
    • Der Katalog reicht von Büro und Handel über Stadt und Haushalt bis zu Übergängen; jedes Geräusch in mehreren Varianten.

    −20 LUFS größte Momentanlautheit, True Peak ≤ −3 dBTP, gemessen nach BS.1770 und gegen ffmpeg geprüft. WAV 48 kHz 24 bit in lib/sfx/final/, OGG für den Prototyp; Herkunft in lib/sfx/roh/herkunft.tsv.

    Requisiten

    Möbel, Geräte, Büromaterial, Dinge im Freien und Zeichen als fertige Bausteine, aus Flächen mit Kontur. Bewegliche Teile wie Schublade, Papierfach oder Telefonhörer lassen sich einzeln bewegen.

    Jede Requisite bietet markup, ids, anker (etwa Tasten als Handziel) und rahmen. Was nur eine Szene braucht, steht in ihrer requisiten.js.

    Gestaltung

    Diese Regeln gelten für jedes Bild im Film.

    • Bühne: 1920 × 1080; Grafik in x 128–1792, y 96–816, Beschriftungen in festen Plätzen darunter.
    • Schutzzone: Die unteren 140 px bleiben frei, damit Untertitel nichts verdecken.
    • Raster: Abstände von 8, 16, 24, 32, 48, 64, 96 oder 128 px.
    • Farben nur aus der Palette: je Szene eine helle Grundfläche und ein bis zwei Akzente.
    • Farbe nie allein: Jede Unterscheidung trägt auch eine Form oder ein Wort.
    • Kontrast: gerechnet, Text ≥ 4,5:1, Grafik ≥ 3:1.
    • Lesetakt: Jeder Text steht lange genug, um ihn zu lesen.
    • Keine Dekoration: keine Schatten, Verläufe oder Rundungen; Schrift Arial.

    Palette der Filme

    Neutral, bis ein Auftrag sein Erscheinungsbild mitbringt; neben jeder Farbe ihr Kontrast auf Weiß.

    {{PALETTE}}

    Alle Werte in tokens/tokens.js, auch Strichstärken (8 / 6 / 4 px), Schrift, Raster und Bühne; ein Auftrag ersetzt nur diese Datei. kontrast() rechnet nach WCAG, lesezeitFrames(zeichen) = (Zeichen / 12) · 30 + 45.

    Prüfungen

    Bei jeder Änderung prüft GitHub die ganze Werkstatt; übernommen wird erst bei Grün. Örtlich läuft dasselbe mit npm run pruefen.

    • Typen und Tests, von den Kurven bis zum Prototyp im Browser.
    • Verbotenes: Schlüssel, Animationen, Zufall ohne Startwert, fremde Farben, Abstände außerhalb des Rasters, Netzaufrufe.
    • Jede Szene wird gebaut und über jedes Bild geprüft.
    • Erzeugte Dateien müssen aktuell sein: Teilesätze, Cue-Listen, Protokolle.

    Prüflauf in .github/workflows/pruefung.yml, Verbotsprüfung in tools/pruefen-verboten.ts. Gestörte Kopien der Vorlage belegen, dass der Build Fehler meldet.

    Begriffe

    ArchetypSkelett einer Figur mit festen Maßen, etwa sitzend im Profil.
    BeatAbschnitt einer Szene mit Anfang, Ende und einer Handlung.
    CueEin Geräusch aus dem Katalog, das an einer Stelle klingt.
    HandzielPunkt, an dem eine Hand sein soll; die Gelenkwinkel rechnet die Werkstatt.
    KontaktbogenNeun Standbilder einer Szene zum Prüfen.
    LautKurzer Ausruf ohne Wort, etwa „oh?“; höchstens einer je Szene.
    PointeDer Moment zum Schmunzeln, nie über eine Person.
    PrototypDie Szene als Webseite zum Abspielen, Anhalten und Springen.
    RegieDie Person, die das Repository führt und entscheidet.
    RigGliederpuppe einer Figur: Gelenke, Längen und die Rechnung, die Winkel in ein Bild übersetzt.
    SchlüsselposePose zu einem Zeitpunkt; dazwischen weich verbunden.
    SchutzzoneDie unteren 140 px, frei für Untertitel.
    TeilesatzDie Zeichnungen aller Teile einer Figur, etwa satz-01.
    TokensDie eine Datei mit allen Farben, Strichstärken und Maßen.
    VorratMehrere Varianten eines Einzelgeräuschs, etwa acht Tastenanschläge, damit sich nichts hörbar wiederholt.

    Zusammenarbeit

    Inhaltliche und gestalterische Entscheidungen trifft die Regie; wo sie entscheidet, bekommt sie zwei bis vier Möglichkeiten mit Empfehlung. Ohne Rückfrage geschieht nicht:

    • neue Abhängigkeit, neue Farben oder Maße;
    • Änderung der Rig-Spezifikation nach Freigabe;
    • Sprech- oder Bildschirmtext umformulieren;
    • etwas generieren, das Kosten verursacht;
    • eine Seite öffentlich machen.

    Solange das Repository öffentlich ist: keine Kundeninhalte, keine personenbezogenen Daten.
